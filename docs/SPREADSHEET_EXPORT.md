# Coordinate-free network documentation export to XLSX / ODS (ELK-06C)

## Contract and user flow

Builder offers **Exportera XLSX** and **Exportera ODS** beside the canonical **Exportera JSON** action. Both spreadsheets are **network documentation, not project/layout backups**. Newly produced `Devices` sheets contain exactly `id,label,kind,zoneId`; there are no X/Y columns, hidden coordinates, or extra layout sheets. `Interfaces`, `Links`, `Zones` and, in schema 1.3, `Project` and `StaticRoutes` contain only explicitly declared supported facts.

`POST /api/export/spreadsheet` receives a full canonical project and `format` (`xlsx` or `ods`). It produces actual binary XLSX/ODS ZIP bytes encoded as base64 with filename `network-documentation.xlsx` or `.ods`. Export reads the current in-memory working project, including unsaved edits, but never saves or mutates the project or server storage. The browser controls the download destination.

## Roundtrip guarantees and explicit boundaries

For **schema 1.0 or 1.3** the exporter validates the complete canonical project, serializes the supported documentation columns, and reimports the generated bytes through the **actual strict XLSX/ODS importer**. It then revalidates both projects and compares their complete object structures, excluding **only node X/Y**. Any altered name, identity, zone, port, enablement, IPv4/MAC/VLAN, static route, cable endpoint, link state, ordering or other supported network field fails closed with HTTP 422. This is an exact **documented network-fact** guarantee, not a false promise of lossless canonical project roundtrip.

After importing a downloaded workbook, Builder computes the first diagram automatically with ELK. Consequently, reimported X/Y may differ from those in the source workspace. Save is still explicit. Preserve exact positions with the separate **.yadilab / JSON project Save/Export**, which keeps X/Y and the complete canonical project.

The workbook has no project-name field: reimport requires an explicit `projectName`. The original name must be supplied if identical name is required. Legacy complete X/Y source workbooks remain *readable*, but new exports and demo templates never include those columns.

**Unsupported representations are rejected rather than silently lost:** explicit null optional MAC/VLAN and explicit empty `staticRoutes`; unknown fields, invalid models, unsupported XML control characters, empty networks, more than 5000 rows, invalid formats and unsupported schema versions. Schema 1.1/1.2 are not migrated. **Schema 1.4 historical `importEvidence` cannot be exported as these schema-1.0/1.3 workbooks**; use the canonical project file instead. Actual ZIP/XML/import safety limits remain binding.

## Verification

`tests/test_spreadsheet_export.py` inspects genuine XLSX/ODS ZIP headers and verifies no X/Y in either schema; compares all documented facts after reimport; rejects data loss; checks determinism, invalid formats and untouched saved project bytes; proves separate canonical layout backup. `tests/test_spreadsheet_templates.py` inspects actual downloaded demo bytes and tests MAC/VLAN/route facts through real import. `tests/browser_smoke.py` downloads both formats in Chromium, verifies the real HTTP payload, imports those same bytes, runs automatic ELK, and requires explicit Save/Open without overwriting previous files.

A workbook is not evidence of network reachability, physical-cable discovery, or authenticity of documented facts. Arbitrary spreadsheet layouts, formulas, hidden/merged cells, macros, and implicit connections remain unsupported.
